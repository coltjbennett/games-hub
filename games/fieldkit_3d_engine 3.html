HOW TO BUILD A GAME FROM THIS FILE

This is a source template, not a separate package you have to build against. Save a copy of this HTML for each new game. All engine code, controls, physics, lighting, textures, and game-specific code live in that one file. You can edit it directly and delete the example sandbox when you no longer need it.

// 1) CONFIG — tune these defaults near the top of the script
const GAME_CONFIG = {
  gravity: -9.82,
  player: { speed: 5.5, jumpSpeed: 5.8 },
  lighting: 'golden-hour'
};

// 2) WORLD — replace buildDemoWorld(engine)
function buildDemoWorld(engine) {
  engine.addBox({
    name: 'Wooden platform', position: [0, 0, 0],
    size: [12, 1, 12], texture: { type: 'wood', repeat: [3, 3] }
  });
}

// 3) GAMEPLAY — add your own weapons, puzzles, enemies, UI,
// win/loss conditions, or replace the character with a vehicle:
// const car = new VehicleController(engine, { position: [0, 1.1, 0] });
// const shot = spawnPhysicsProjectile(engine, { speed: 35 });
// const placed = placeBoxOnGrid(engine, { grid: 1, size: [1,1,1], texture: 'stone' });

Procedural materials: put texture: 'grass', texture: 'wood', or texture: { type: 'brick', repeat: [3, 2] } directly in an addBox or addSphere call. Available types include concrete, asphalt, grass, sand, wood, metal, brick, stone, tile, hazard, fabric, marble, checker, and circuit. Custom Three.js meshes can use setProceduralTexture(mesh, 'stone').

Genre starting points: For a shooter, use the included raycastFromCamera(engine) for hitscan weapons or spawnPhysicsProjectile(engine, options) for physical projectiles. For a platformer, tune the existing character's jump, acceleration, camera and gravity. For driving games, the included VehicleController handles a Cannon-es raycast car, suspension and wheel visuals. For building games, placeBoxOnGrid(engine, options) gives you grid-snapped placement with procedural materials. These helpers are all source code inside this same HTML file; edit them or replace them as your game needs.

Included in the base: fixed-step physics, friction and restitution profiles, dynamic rigid bodies, capsule-style player collision, slope checks, coyote time, jump buffering, mouse capture and drag look, mobile joysticks/buttons, multitouch, camera collision, adjustable lighting and fog, runtime tuning controls, and reusable procedural textures.

A realistic limitation: this is a flexible starter engine rather than a finished AAA engine. The default character uses a dynamic capsule approximation; complex staircases, high-speed vehicles, huge worlds, networking, animation rigs, and advanced weapon systems will need game-specific code. The CDN imports mean the browser needs internet access when loading the file.
